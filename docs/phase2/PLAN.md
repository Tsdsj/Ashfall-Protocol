# 第二阶段执行与验收计划

范围来源：项目根目录 `goal2.md`，119 个章节。原文保留。用户已要求继续实现，且第 1、118 节明确要求检查后直接修改；本轮沿用现有界面设计，不另设设计审批。

## 执行顺序

1. **当前版本实际审查与参考研究（1–2、97–99、105–108）**：运行完整生存链路，记录移动、身体、武器、角色、环境、声音与主线缺口；形成修改前的证据。
2. **第一人称与动作基础（3–18、59–62、109–113）**：保留直接鼠标输入，加入有约束的速度变化、共享步态、分层镜头与武器弹簧、身体代理、ADS / 冲刺 / 姿态 / 落地 / 翻越 / 换弹过渡、手部和交互动作。验证帧率独立性、准心一致性和降低动态效果设置。
3. **角色、AI 与物体（19–41）**：门完整状态与碰撞同步、角色混合动画、攻击命中帧、方向受击、失衡 / 倒地 / 起身 / 多种死亡、视线外生成、持续状态、局部避让、绕障与门窗交互。验证玩家可闪避攻击、门后安全边界、生成可见性和持久化。
4. **资产与环境（42–52、89–92、102–104）**：获取并核验真实免费资产与动画来源，优化模型和纹理、统一材质与尺度、按距离加载 / LOD；为森林、住宅、城市、工业区、军事区、道路和室内建立不同的环境构图与故事；提升天气、夜晚和手电反馈。
5. **玩法与叙事（53–58、63–79、93–96）**：有时间与风险的搜索、区域物资与独特奖励、资源和敌人感知联动、强度导演；Act 1–4 + Finale、至少三个有条件差异的结局、5–10 条支线、引擎内可跳过的过场、可复用 SequenceController 及实际剧情事件。
6. **声音与界面（60–62、80–88）**：分层武器、命中材质、状态化感染者声音、按材质 / 速度 / 姿态 / 负重变化的脚步、室内外混响、变化与冷却；短 UI 转场和背包完整反馈。
7. **最终品质与稳定性（100–104、114–119）**：逐项实际进入游戏检查 17 个品质领域，回答第 117 节所有问题；完成三结局、支线、跳过 / 重载、WebGPU / WebGL2、旧存档迁移、离线、画质差异和最终 30 分钟持续运行检查。

## 实施约束

- 背包、存档、分块和制作采用增量扩展；不重写稳定系统。
- 美术品质以实际画面和动作审查为依据，不用模型数量代替质量。
- 剧情选择、奖励、场景变化与已播放过场进入持久状态；跳过不能丢失必要状态。
- 新资产保存作者、来源、授权、修改、用途和校验值。大型资源按需加载，避免拖慢菜单和新世界。
- P0 移动、镜头和战斗先于边缘内容。任何反馈动效都不能延迟鼠标视线或攻击判定。

## 证据与完成判定

`requirements.json` 保留 119 节原始要求文本及逐项状态。每项应包含对应实现位置、适用自动检查、实际浏览器证据和审查结论。功能要求用真实操作证明；画面、声音、动作和整体体验必须有实际运行审查，不能仅凭类型检查或测试为绿而通过。

阶段完成时更新证据，保持未完成条目明确可见。全部要求和最终 DONE 条件得到足够证据后才结束本轮。

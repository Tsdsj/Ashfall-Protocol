## P1：影响世界可信度、玩法闭环或真实功能的缺口

### G01 · 自建安全屋仍不能成为天气庇护

- **章节**：53、54、90、93、97、115、119。
- **代码事实**：`src/simulation/simulation.ts:256` 的 `indoors` 仅遍历 `gen.pois`，不检查 `state.structures` 中的 roof/floor/wall；这个值继续传入 `updateSurvival`、雨粒子和室内声音。`src/simulation/survival.ts:42` 在 `rain && !indoors` 时增加湿度。
- **已复现**：在 POI 外放置有效地基和屋顶，把玩家置于屋顶正下方；雨天更新 0.05 秒后 `indoors=false`、`wetness=0.016`。建造出来的遮雨结构不挡雨，营地保温的核心收益没有兑现。
- **执行项**：提取统一遮蔽查询，至少区分头顶遮雨与封闭室内，并让生存、雨粒子、混响共用结果。损坏/拆除屋顶要立即失效；不能只判断“附近有 roof”。
- **验收**：空地淋雨 → 自建屋顶下停雨 → 四墙封闭后保温增强 → 拆掉屋顶恢复淋雨；保存重载后一致。

### G02 · DirectorState 目前是未接入的存档数据

- **章节**：53、54、93、94、95、115、119。
- **代码事实**：`src/simulation/quality-state.ts:17` 初始化 tension/lastCombat/recoveryUntil/lastEvent/encounters；当前源码对这些字段的其余引用仅是类型和存档校验。`src/simulation/population.ts:313` 的 `director()` 主要按 220–380 秒间隔、随机角度和均匀事件表挑选，只有生命低于 30 时直接返回，没有使用刚刚经历的战斗、资源、恢复期或持续噪声。
- **影响**：新增了 Director 的名字和保存字段，但没有兑现 Safe → Tension → Combat → Recovery 的节奏。
- **执行项**：接入射击/受伤/追击等事件更新 tension 和 lastCombat；用健康、饮水/食物、弹药与位置调整事件预算；恢复期降低高压遭遇，避免在低资源时只弹一句提示。
- **验收**：同种子下比较安静探索、连续交火、濒死恢复三种情境，记录 Director 决策及其不同；必须看到实际遭遇节奏差异。

### G03 · 随机事件中“求救、车队、残骸”还是换名字的补给箱

- **章节**：53、55、57、89、95、96、115、119。
- **代码事实**：`src/simulation/population.ts:333` 定义事件表；`airdrop/convoy/wreck/rescue` 都只创建一个 `ContainerData`，区别主要是 medical/military loot；`src/rendering/renderer.ts:277` 把 event 绘制为通用掉落容器。没有求救者、来袭者、营救条件、车队车辆或坠机残骸对象。`WorldEvent.resolved` 当前没有置为 true 的业务路径。事件表使用均匀 `choose()`，尚无 Rare Event 单独概率/前置条件。
- **执行项**：先完成 3 个可玩的原型事件：幸存者遇袭（保护/救助/结果）、废弃车队（实际车辆、警报与危险回报）、罕见残骸（可见残骸、低概率与一次性独特成果）。补 resolved/失败/过期后的世界后果，避免继续增加只有名称的种类。
- **验收**：接近事件时存在与名称一致的实体与操作；完成后事件状态、奖励、地图标记与重载结果正确；罕见事件确实与普通事件使用不同发生条件。

### G04 · 搜刮计时有了，但箱盖、冰箱门与车辆门没有可执行实体动画

- **章节**：13、14、19、20、55、97、99、116、119。
- **代码事实**：`src/core/game.ts:520` 搜刮已有计时、声音和动作，是有效进展；但 `src/rendering/buildings.ts:486` 的容器仍是单个 `batch.box`，没有 lid/pivot。`src/rendering/objects.ts:76` 的 storage、`:182` 的 fridge 没有可开关部件；车辆两侧门在 `vehicleModel()` 中被并入静态 ModelBatch，只返回 root/meshes/wheels。车辆进入虽有 0.65 秒动作，车门状态并不参与。
- **执行项**：为常见箱子、冰箱和车辆至少各做一个独立铰链部件，将搜刮/开储物/上下车过程驱动到实体动作；受阻、取消和重复交互保持一致。不要仅再加一个等候条。
- **验收**：实际看到手与物体同时响应；打开后不是原封不动的闭合模型；暂停、取消、重载不会留下半开但不可交互的状态。

### G05 · 收获不是原子事务，会吞掉种子奖励

- **章节**：53、54、85、87、105、119。
- **代码事实**：`src/simulation/building.ts:174` 先 `addItem(turnip,3)`，再不检查结果地 `addItem(seeds,2)`，随后重置 growth/plantedAt。
- **已复现**：空 1×1 背包收获，返回 true，萝卜 3、种子 0，作物状态已清空。玩家看到“收获成熟作物”，循环种植所需种子却丢失。
- **执行项**：沿用已有背包副本事务，一次性校验全部产物；装不下时保留成熟作物和全部奖励。
- **验收**：只装得下萝卜、只装得下种子、两者都能装、重复点击、保存重载五种情况；不得部分领取后清空植株。

### G06 · 上层地板与木台阶的空间能力不匹配

- **章节**：14、39、53、54、57、97、119。
- **代码事实**：`src/simulation/building.ts:61` 放置 floor 时固定加 3 m；`src/rendering/objects.ts:54` 的 stairs 仅四级低台阶，最高约 0.36 m；`src/simulation/collision.ts:224` 的 stairs 地面计算峰值也只有 0.25 m，且使用绝对 dz 忽略旋转。不存在可连接 3 m 上层地板的梯段/梯子放置流程。
- **影响**：已有地板组件很容易形成看得到、正常移动到不了的上层；视觉台阶和碰撞坡度也不一致。
- **执行项**：明确区分低台阶与层间楼梯，并提供与现有 3 m 层高匹配的构件；或者把当前 floor 明确限定为地面铺板。坡面/旋转、支撑和入口都要共用几何数据。
- **验收**：通过实际放置流程搭建可从地面步行到二层的安全屋；转向 90°、上下行、AI 追踪与保存重载一致。此项未做浏览器复现，依据生成与碰撞高度的确定性不匹配。

### G07 · 手电仍无限使用，也没有自身阴影

- **章节**：54、80、91、92、115、119。
- **代码事实**：`PlayerData` 仅有 flashlight:boolean；`src/simulation/simulation.ts:263` 只消耗 torch 耐久，没有手电电量消耗。`src/rendering/environment.ts:102` 明确 `flashlight.shadowEnabled=false`。`src/audio/audio.ts:501` 的低电量逻辑寻找物品 ID `flashlight`，而 `src/data/items.ts` 未定义该物品，因此这个分支正常游戏不可达。
- **执行项**：为现有手电定义可保存的电量与补充来源、低电量反馈，并在合适画质配置上启用有预算的手电阴影/遮挡。声音读取同一个真实电量来源。
- **验收**：满电 → 低电 → 熄灭 → 更换/充电 → 保存重载；站在墙后或物体背面不能被手电照穿。明确 Low 的性能替代。

### G08 · 动物仍停留在统一 primitive 身体与四肢正弦摆动

- **章节**：14、15、16、42、43、49、59、97、99、109、115。
- **代码事实**：`src/rendering/characters.ts:42` 的鹿/猪/狼复用球体身体和圆柱腿；`animateAnimal():663` 主要是同一种四肢 sin 摆动、攻击时统一加摆幅、死亡整根 root 侧倾。人形使用了外部绑定动画，但动物没有相当层级的步态、扑咬接触、受击姿态与脚部贴地处理。
- **执行项**：优先完善最常见的鹿和狼：匹配四足步态、真实攻击接触阶段、受击与倒地；资源可用时替换几何。此项是确定的动画覆盖差距，最终“是否明显廉价”仍应由实机场景判断。
- **验收**：坡面行走、转向逃跑、狼扑咬、侧向中弹与死亡；物理命中帧和身体动作对齐，不能仅拍一个静止动物截图。
